# Phase 1 — Class Lifecycle Monitor

**Status:** Implemented and smoke-tested  
**Date:** 2026-10-05  
**MVP parent checkpoint:** `7a94cdf`

## Scope of this increment

This is the first isolated increment of the Class Lifecycle Monitor & Verification Ledger architecture. It implements the monitoring canvas and automatic timeline classification only. Certification sign-off gates and the tamper-evident QR ledger remain subsequent increments.

## Interface

Admin now presents a prominent **Open Class Monitor** action. It opens the dedicated, responsive **Class Status & Verification Hub** overlay with four columns:

1. Scheduled
2. Ongoing
3. Almost Done
4. Done (Pending Audit)

The matrix is keyboard-readable, responsive, horizontally scrollable on narrow devices, and can be refreshed without closing the window.

## State engine

Each saved enrollment appears in exactly one state. Classification uses its saved start/end dates, session matrix, optional recorded completed hours, and the current device time:

- **Scheduled:** first session is in the future, or the record does not yet have a usable schedule.
- **Ongoing:** the run has begun and more than two sessions remain.
- **Almost Done:** one or two scheduled sessions remain.
- **Done:** the schedule endpoint has passed or recorded instructional hours meet the required hours.

Done records display **Certification Clearance Pending**. This warning intentionally does not yet unlock certificate actions.

## One-day workshops and operational changes

A one-session workshop remains **Almost Done** throughout its entire scheduled local calendar date, regardless of whether its saved end time has passed. It moves to Done after that date ends.

The monitor provides two explicit record actions:

- **Move workshop +7 days:** available only for one-session workshops. It preserves the weekday, updates start/end/session dates, shifts a matching payment due date, and records both the cancelled and replacement dates in the audit history.
- **Mark dropped:** releases certification eligibility and records that the seat is released. Existing charges and payments are preserved for manual reconciliation. Restoring the enrollment is also audited.

## Boundaries

- No pricing, discount, payment, margin, refund, or catalogue formulas were changed.
- No certificate can be generated by this increment.
- Multi-role sign-offs, certificate rendering, and QR integrity records are not included yet.
- Device-local date and time are authoritative in this local-only application.
